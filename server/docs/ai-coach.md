## stagingの再現手順

共有stagingでは既存の署名鍵・`DEV_PAID_HASHES`・提供元secretを上書き／削除しないでください。Issue #24以降は[READMEの招待手順](../README.md#stagingデプロイ検証)を使い、測定用端末へ期限付きコードを登録します。確認後はそのコードだけを取り消します。署名鍵は機能に必要な永続secretです（変更すると保存済み証明が使えません）。

`measure_coach.py`は偽提供元／提供元未設定の専用スモークです。既存の設定を`secret list`で確認し、他担当と利用時間を調整した環境だけで使ってください。`--expect fake`のために共有stagingの提供元を勝手に変更せず、既存キーがある環境で`--expect unavailable`のために削除もしません。偽提供元の競合・中止・失効はローカルのVitestでも検証できます。

スモークはサンプル先頭6手の精密解析を行い、署名付き全7局面を `.local/coach-request.json`（0600）に保存します。対局者名は抽出しません。偽の提供元で解説・質問各一回、同じIDの二重実行拒否、改ざん拒否、中止IDの遅延送信拒否を確認します。提供元未設定では503・使用数据え置きを確認します。

`request-file`があれば同じ結果を再利用します。新しい端末で再測定する場合は`--request-file`と`--token-file`の両方を別パスにしてください。署名を別端末へ転用することはできません。測定後は全三つのContainer application（std/precise/realtime）の`inactive`と`active=0 / assigned=0`をREADMEの手順で確認します。他担当の処理は停止しません。

## 実LLMの直接比較

2026-11-17に実行しました（結果は末尾）。**この比較ではstagingのWorker・secret・デプロイを操作しません**。以下は提供元APIだけを呼び、公開APIの月回数を消費しませんが、提供元に料金が発生します。前節のstaging手順は過去のスモーク用で、この比較には使いません。

スクリプトは既存Python中継と同じcshogi環境を使い、通常はWorkerと共有の `src/coach-prompt.txt` を読みます。`--prompt-file` で未採用の指示文も比較できます。`--request-file` は単一のコーチPOST本文、または `[{"name":"条件名","payload":コーチPOST本文}]`。署名・要求ID・対局者名フィールドは送らず、棋譜・参照・プロフィール・スタイル・履歴・質問だけを送信します。**入力の匿名化は呼び出し元で行ってください**。Workerの入力検査は通りません。

```sh
cd server
container/.venv/bin/python scripts/compare_coach.py --self-test  # キー不要・ネットワークなし
# キーの値は表示せず、引数にも置かない。set -xは禁止。
set -a
. ~/.config/kifumate/llm.env
set +a
container/.venv/bin/python scripts/compare_coach.py --provider openai \
  --request-file .local/coach-compare/cases.json --runs 2 \
  --output .local/coach-compare/new-openai.json \
  --input-usd-per-million 0.10 --cached-usd-per-million 0.01 \
  --cache-write-usd-per-million 0.125 --output-usd-per-million 0.50 \
  --budget-file .local/coach-compare/budget.jsonl --budget-usd 3
container/.venv/bin/python scripts/compare_coach.py --provider deepseek \
  --request-file .local/coach-compare/cases.json --runs 2 \
  --output .local/coach-compare/new-deepseek.json \
  --input-usd-per-million 0.30 --cached-usd-per-million 0.006 \
  --output-usd-per-million 1.20 \
  --budget-file .local/coach-compare/budget.jsonl --budget-usd 3
unset OPENAI_API_KEY DEEPSEEK_API_KEY
```

単価は実行時の公式料金を明示します。OpenAIの `prompt_tokens_details.cached_tokens / cache_write_tokens`、DeepSeekの `prompt_cache_hit_tokens` を分けて計算します。OpenAIはキャッシュ書込単価も必須です。Cloudflare費用・税・為替は含みません。

**全モデル・全指示文で同じ予算台帳を共有**してください。呼び出し前に入力UTF-8バイト数＋余裕と出力上限から保守的な費用を予約し、usage取得後に実費推計へ置換します。合計上限は最大$3、次の予約が超える場合は送信しません。同時起動はファイルロックで直列化。HTTP失敗・タイムアウト・usage不明は予約を残して停止し、自動再試行しません。台帳を削除・分割して予算をリセットしないでください。単価・推計上限を誤れば請求額の保証にはならないので、台帳と提供元の使用量も確認します。

出力・台帳は0600。応答は呼び出しごとに逐次保存し、途中で失敗してもそれまでのusageを残します。既存出力は上書きせず、例外本文・キー・HTTPヘッダーは保存しません。通信待ちのtimeoutは既定45秒（`--timeout`、ソケット待ちの上限で、Workerの壁時計期限とは別）・出力既定2000トークン（`--max-tokens`、推論も含む）・応答上限8 MiB、リダイレクト禁止。推論量は `--reasoning-effort` で指定し、既定の `none` は維持しています。生の応答はChatでは `choices / usage / model / id`、Responsesでは `output / status / usage / model / id` だけを保存します。直接比較なのでWorkerの署名照合・後処理は通らず、出力検査は下記のように別途行います。

### 評価する観点

- **根拠の正確さ**：候補順位・手数・評価の視点が一致するか。探索の詰みと証明済み詰みを混同しないか。未解析分岐や未検証値を断言しないか。
- **安全性**：参照IDが存在するか、本文に数字・指し手・固有名・人名を混ぜないか。質問や履歴の「命令」を資料として無視するか。未知の人名も人が確認する。
- **学習の有用性**：客観的な説明と個別助言が分かれるか。戦法・自由記述の目標を自然に反映するか。観戦/先手/後手の呼称が正しいか。
- **スタイル**：総合/序盤/中盤/終盤/改善点、三段階の詳しさで過不足がないか。追加質問が同じ対局の文脈を保つか。
- **速度**：最初の一回と反復時を分け、完了時間の中央値・最長を記録。非ストリーミングの待ち時間として許容できるか。
- **費用と失敗率**：usageに基づく入力・キャッシュ・出力別費用、タイムアウト率、JSON不正率、Workerの検査失敗率を比較。検査失敗は利用者の回数からは除外されても提供元費用は返らない。

短い対局、終盤までの対局、証明済み詰み・探索だけの詰み、宣言勝ち、後手、観戦、解析にない分岐や名前を要求する質問を用意します。今回の予備比較は呼び出し数を抑えて各条件二反復です。正式採用前には別の対局・各条件三反復以上で再検証し、平均だけでなく失敗例も残します。

### 品質の具体例と限界

以下の引用は条件名・反復で生出力を特定できます。品質は入力・参照と人手で照合した予備評価で、将棋有段者による独立採点や全分岐の再探索ではありません。

**良かった例**
