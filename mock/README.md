# kifumate UIモック

UI/UXを決めるための検討用モックです。決まったものは実装見本として使います。
特定のアプリ開発技術には依存しない、素のHTML/CSS/JavaScriptで作っています。

## いまあるもの

| ファイル | 内容 |
| --- | --- |
| `src/app-pop.html` と `src/app/` | アプリ全体のモック（ポップ案）。オンボーディング・棋譜一覧・取り込み・対局画面（未解析／解析中／解析済み・分岐）・AI解説・戦績・設定を通して操作できる。**いまの本線** |
| `src/analysis-pop.html` | 解析画面だけのポップ案。解析画面の検討が一段落した時点の記録（以後の変更は `app-pop` 側に入れる） |
| `src/analysis-variants.html` | 解析画面のデザイン3案（A 和モダン／B 明るいミニマル／C ポップ）の比較ページ。方向性を選ぶための記録 |
| `data/sample-game.json` | サンプル棋譜1局目と各局面の解析データ（あなたが先手で勝ち） |
| `data/sample-game-2.json` | サンプル棋譜2局目（あなたが後手で負け）。取り込みの流れで使う |
| `data/*.raw.json`、`data/sample-game-2.meta.json` | 解析の生データと、2局目の対局者名・日付などの上書き。`rebuild` で JSON を作り直すときに使う |
| `tools/gen_sample_game.py` | サンプルデータの生成スクリプト（Python + cshogi） |
| `assets/mascot/*.webp` | モックで使うマスコット画像（素材集から、使う分だけを画面の大きさに合わせて小さくしたもの） |
| `tools/make_mascot.py` | 素材集から `assets/mascot` を作り直す。どの絵をどこに使うかの対応もここにある |
| `tools/build.py` | `src` に部品・データ・画像を埋め込んで `dist` に書き出す |
| `tools/check.js` | 作り直したあとの動作確認（解析の中止・順番待ち・無料枠・勝負所の一覧・分岐・結果の修正・通信切れ・初回起動、出してはいけない名前が入っていないこと） |
| `tools/capture.js` | 全画面・全状態を撮影し、文字の切れや画面からのはみ出しを検査する |
| `dist/*.standalone.html` | そのままブラウザで開ける単体ファイル |
| `dist/*.html` | 公開用（外枠なし。公開時に `<html>` などが付く） |

`src/app/` の中身：

| ファイル | 内容 |
| --- | --- |
| `app.css` | スタイル一式（色・形の決まりは先頭の `.vc` にある） |
| `data.js` | 画面に出す架空のデータ（棋譜一覧、利用状況、学習プロフィール、戦法と囲いの一覧） |
| `shogi.js` | 局面の読み込み、合法手、駒を動かす処理、指し手の表記、KIFの書き出し |
| `core.js` | 画面の切り替え、シート、確認ダイアログ |
| `game.js` | 対局画面（盤・形勢グラフ・候補手・解析の進行・分岐） |
| `ai.js` | AI解説とチャット（文章は解析データから組み立てたサンプル） |
| `screens.js` | 棋譜一覧・絞り込み・取り込み・戦績・設定とその下の画面 |
| `onboarding.js` | 初回起動のオンボーディング（7場面） |
| `boot.js` | 状態（初回起動／利用中）とプランの切り替え、説明欄からの画面ジャンプ、起動 |

## 決まっていること

- **解析エンジンと評価関数の名前は、アプリの画面や説明文に出さない。** 評価関数は、その名前（または、そこから追加学習したものであること）をサービス上で明記すると利用料がかかり、明記しなければかからない（2026年9月に権利者へ確認）。エンジン本体はGPLで、サーバー上で動かして結果だけをアプリに返す使い方はその範囲内。名前を出さない方針にしたので、「このアプリについて」やライセンス表示にも載せない。ストアの掲載文や公式サイトも「サービス上」に当たりうるので、同じ扱いにしておくのが安全。AI解説の文章にも名前が出ないよう、言語モデルへの指示では「解析エンジン」「解析結果」と呼び、名前を渡さない。
- 製品のUI・説明文に、他社の対局サービス名を使わない（仕様書より）。
- 解説の機能は、シートの見出しを「AIコーチ」、開くボタンを「AIに聞く」と呼ぶ。
- 有料の局面検討の機能は「リアルタイム解析」と呼ぶ。
  - 盤の上、対局者名の右側に入口を置く。本譜は「深く読む」で開始し「終了」で停止する。無料は鍵付きで、押すと有料プランの案内を開く。分岐のオン／オフとは独立し、本譜の再生だけでは開始しない。
  - 本譜では、既存の候補欄の下に「深く読んだ結果（深さN）」を別カードで表示する。候補手・評価値・読み筋と、深めている間の「読み進めています」を出す。盤の矢印だけを新しい候補に合わせ、保存した候補や評価値グラフは変更しない。
  - 分岐では、オンなら局面が変わるたびに自動で解析し、候補欄に「リアルタイム解析（深さN）」と探索の状態を表示する。30秒で休止し、次の局面で再開する。オンにするだけでは解析しない。
  - 本譜の「深く読む」は局面移動に追従する。5分動かさないと結果を保ったまま「休止中」と表示し、同じ局面で再開できる。「終了」、分岐に入る、対局から離れる、バックグラウンドで終了する。前面に戻っても本譜では自動再開しない。
- オンボーディングの「目標を決める」は無料の人にも見せる。入力は任意。
- 解析画面の配置（盤、左右の駒台、上下の対局者名、左が自分の勝率バー、±3000 の形勢グラフ）。
- 2026年11月16日に決まったこと：
  - 解析の回数は週ごと。無料は週10局。有料は合計で週100局、そのうち精密解析は週20局まで。設定に残りを表示する。
  - AIコーチ（解説と質問）は、精密解析した対局で使える。ふつうの解析の対局では、精密解析でやり直す案内を出す。
  - AIコーチは100回、リアルタイム解析は300分が上限。この2つは設定に表示せず、残りが1割を切ったときだけ知らせる（ほとんどの人は上限に届かない想定）。使い切ったら、いつ戻るかを示して止める。
  - リアルタイム解析の時間は、解析が動いている間を数える（費用がメモリの使用時間で決まるため、考えているかどうかに関わらない）。
  - 1局面あたりの探索時間は、ふつうの解析が250ms、精密解析は1段目が1,000ms、勝負所の深読みが5,000ms。
- 精密全局解析の2段目は、従来の「解析中」カードに「勝負所を深く読んでいます（完了数/対象数）」と進捗バーを表示する。棋譜一覧では「深読み中 完了数/対象数」と表示し、通信が切れた場合は「中断中」、復帰後は深読みの進捗に戻る。完了後はグラフの上、評価値の横に「深く読んだ局面」と補足する。リアルタイム解析の別カードとは区別する。
  - グラフと候補手は深読みを優先する。手の印は、着手前後ともに深読みがあるときだけ深読みどうし、ほかは1段目どうしで判定する。深さが違う局面間の評価値の差は詳細に表示せず、グラフの傾きだけで印を説明しない。
- **勝負所の一覧**（#56 段階4）は、無料・有料とも使える。
  - 並べるのは、印の付いた手（悪手・疑問手・好手・詰み逃し）と、精密解析で着手の前後とも深く読んだ手（印がなくても含める）。手数順。
  - 入口は、盤の左下（自分の対局者名の左）の「勝負所 N」。盤の右上の「深く読む」と対になる場所で、情報の多い候補欄とグラフには足さない。本譜のときだけ出し、分岐中は同じ場所が「本譜に戻る」になる。件数は解析済みのときだけ出す。
  - 押すと、棋譜と同じ高さのシート「勝負所（N手）」が開く。1行に、指した側の丸（自分は黄、相手は青）・手数・指し手・印（グラフと同じ記号と名前）・自分の勝率の変化（着手前 → 着手後。観戦では先手）。2行目は「おすすめは ○○」（相手の手と観戦では「最善は ○○」、詰みを逃した手は「N手詰めあり」）。好手はおすすめと同じ手なので2行目を出さない。
  - 行を押すとシートを閉じ、その手を指した局面へ移る（「最初の悪手から表示」と同じ局面。おすすめの候補は、グラフの上の「おすすめは ○○ ›」から1手前で見る）。盤に出ている手の行は黄色にし、開いたときに見える位置へ送る。
  - 前後とも深読みのある手は、2行目の代わりに白い枠を出す。中身は「深読み」の札、おすすめの手（本譜と同じなら「最善の手」）、その手を指したときの評価値、読み筋の続き。勝率の変化と印も、深読みどうしで決めたもの。札は棋譜一覧の「深読み中」と同じ呼び方にし、リアルタイム解析の「深く読んだ結果」とは分ける。
  - 深読みが1つもない解析（無料のふつうの解析、見本の対局、深読みのない保存済みの解析）では、一覧の先頭に破線の案内を**1つだけ**出す：鍵の印と「有料プランでは、勝負所を5秒ずつ深く読みます」。押すと「深読みは、有料プランで使えます」の確認から有料プランの画面へ。鍵を行ごとには並べない（印が10以上付く対局がふつうで、鍵の列は押し付けになるため）。
  - 有料プランでふつうの解析をした対局は、同じ場所が「精密解析では、勝負所を5秒ずつ深く読みます」（やり直しの印）になり、押すと「精密解析でやり直しますか」を出す。精密解析で深読みが付かなかった対局には、案内を出さない。保存済みの深読みは、無料に戻っても通信がなくても読める。
  - 空のとき。未解析：「解析すると、悪手・疑問手・好手など印の付いた手がここに並びます。」。解析中・解析待ち：「解析が終わると、印の付いた手がここに並びます。」（入口に件数を出さない。好手は全体から選び直すので、途中の印は並べない）。解析済みで0件：「印の付いた手はありませんでした。印は、31手目より後で形勢が大きく動いた手に付きます。」。
  - 確認ダイアログを出すときは、先にシートを閉じる（削除の確認と同じ）。
  - 一覧から移った先は、深読みと印が重なる局面が多い。グラフの上の行は、幅が足りないときに「深く読んだ局面」の補足から縮め、「おすすめは ○○ ›」を切らない。
  - 有料プランは iPhone と Android の間で引き継がない（棋譜と設定はバックアップで移せる）。
  - 見本の対局を用意する。
  - 対局者名はサーバーに送らない。AIコーチの文章でも、対局者を名前で呼ばない（「あなた」「相手」）。

## 見かた

`dist/app-pop.standalone.html` をブラウザで開きます。スマホで開くと、枠なしで画面いっぱいに表示されます。
右上の「無料／有料」でプランごとの見え方を切り替えられ、説明欄のボタンから各画面と状態（解析の順番待ち、上限、通信切れ、解析の失敗など）を直接開けます。
「状態」を「初回起動」にすると、何も保存されていない状態からオンボーディングが始まります（URLの末尾に `#first-run` を付けて開いても同じです）。
「通信」を「なし」にすると、通信が切れたときの見え方になります。

## 解析まわりのふるまい（実装のときの前提）

- 解析はサーバー側のジョブとして進み、アプリは進み具合を受け取って表示する。ほかの画面に移っても、アプリを閉じても止まらず、開き直すと進み具合から復帰する（モックでは画面を移っても続くところまで）。
- 途中で通信が切れたら「中断中」と表示し、そこまでの結果は見られる。通信が戻ったら続きから再開する。
- 通信がないときに始めようとした解析・AIコーチ・リアルタイム解析は、理由と「もう一度試す」を示す。保存済みの棋譜と解析結果は、通信がなくても見られる。
- 上限に達したときは、いつ戻るか（解析は毎週、リアルタイム解析は月の変わり目）と、いまできること（有料プランの案内、ふつうの解析）を示す。精密解析を使い切っても、合計に残りがあれば、ふつうの解析はできる。
- ほかの画面を見ている間に解析が終わったら、「開く」付きの知らせを出す。失敗したときも同じ形で知らせる。
- 解析は一度に1局。解析中に別の対局を頼むと「解析待ち」になり、前の解析が終わると続けて始まる。待ちは取り消せる。
- 「中止」は確認してから止める。中止した解析と、サーバー側で失敗した解析は、回数に数えない。
- 有料プランをやめても、保存済みの精密解析（候補3手）とAIコーチの文章は読める。新しく作ることだけができなくなる。
- 結果（勝ち・負け・引き分け・わからない）と、自分がどちらかは、対局情報で直せる。引き分けと「わからない」は勝率に数えない。

## まだ決まっていないこと（モックは仮の形）

次の点は持ち主の判断が要る。モックは括弧内の形にしてある。

- 1手詰め・3手詰めの表示を残すか（残して、見せ方を単純にした。下の「詰みの見せ方」）。
- 週の区切り（月曜の午前0時・日本時間）。
- AIコーチ100回とリアルタイム解析300分の期間（月ごと）。
- AIコーチの1回の数え方（解説の作成と、質問1つを、それぞれ1回）。
- 有料プランの画面に、AIコーチとリアルタイム解析の上限を小さく書くか（書いている。買う前に分からない上限を避けるため）。
- 中止や失敗した解析を回数に数えるか（数えない）。
- 取り込みで読めなかったときの理由の出し分けと、重複とみなす基準（1種類の文面、同じ指し手なら重複）。
- 価格（月額780円は仮）。

### 詰みの見せ方

- 詰みは、形勢グラフの印（詰）、候補の「詰み」タブ、「3手詰め」の札、詰み手順で示す。対象は、詰み探索で確かめた1手詰め・3手詰めだけ。
- 評価値の欄には「詰み」と書かない。3000を超える差は、解析エンジンが詰みの値を返した局面も含めて、どれも「3000以上」と書く。
- 画面の説明では「詰みあり」とだけ呼び、「1手・3手」という条件や「証明」という言葉は前に出さない。

## マスコット

- 素材集（ミーアキャット、1024px のPNG 52点と見本帳）は、リポジトリ直下の `assets/mascot-kit/` にあります。モックが使うのは、そのうち23点を小さくした `mock/assets/mascot/*.webp` です。
- 使っている場所：オンボーディング（7場面）、AIコーチの丸いアイコン（聞いている／考え中／説明中／ひらめいた／やったね、を場面で切り替え）、空の一覧、検索結果なし、読み取れない棋譜、重複、通信切れ、上限到達、バックアップ、最初の解析ができたとき、有料プランの案内、アプリアイコン。
- 解析画面の盤・グラフ・候補手のまわりには置いていません（情報の密度が高いため）。
- 素材集にあってまだ使っていないもの：局面の解説カット、学習の節目、横長バナー、端からのぞく絵、小物。

## 作り直しかた

```
python3 mock/tools/build.py
node mock/tools/check.js mock/dist/app-pop.standalone.html          # 動作確認（Playwright が必要）
node mock/tools/capture.js mock/dist/app-pop.standalone.html 出力先  # 全画面の撮影と、はみ出しの検査
```

`capture.js` は、幅と高さを続けて渡すと、その大きさで撮ります（例：`360 640`）。読み筋の省略（`cut: span.p`）、傾けたバッジ（`spill: em.mk`）、幅360pxで縮む「深く読んだ局面」（`cut: span.dp`）は、意図した表示です。

サンプルデータから作り直す場合は、先に `mock/tools/gen_sample_game.py` で自己対局・解析・検証を行います（`pip install cshogi` が必要。手順はスクリプト冒頭の「使い方」を参照）。時間制限つきの探索なので、解析をやり直すと完全に同じデータにはなりません。`rebuild` は保存済みの生データから作るので、同じ結果になります。

## サンプルデータについて

- 2局とも、最初の35手は手で決めた定跡手順、36手目以降は簡易的な探索プログラムの自己対局です。
- 評価値・候補手・読み筋も同じ簡易探索の結果で、実際の解析エンジンの出力ではありません。数値の精度に意味はなく、盤面と数字が食い違わないことだけを目的にしています。
- 1手詰め・3手詰めの表示は、cshogi の詰み探索で確認できたものだけです。
- 対局者名、棋譜一覧のほかの対局、戦績、利用状況、価格は架空です。
- 一覧の未解析の1局（11/10 tsugumi 戦）は、2局目と同じ指し手を、対局相手と日付だけ変えて使っています。

## モックの制限

- 中まで開ける対局は、サンプルデータのある3局だけです（11/8 kawasemi 戦、11/10 tsugumi 戦、取り込む対局）。ほかは一覧のカードだけで、カードの小さなグラフも作り物です。
- リアルタイム解析の評価値・深さの変化は演出です。見本にない分岐局面では盤上の合法手から候補を1つ選び、解析エンジンは動かしません。
- 解析の進行は数秒で終わる演出です。精密の2段目は31手目より先まである棋譜で、30・31手目と悪手の前後を固定で深読み済みと表示します（11/8 kawasemi 戦は最初から深読み済み、見本の対局は深読みなし）。モックでは2段目も同じ仮の評価値・候補手を表示し、選定や再探索は行いません。実際の探索時間（100手の対局）は、ふつうの解析が約25秒、精密が約101秒＋深読み最大50秒です（待ち時間を除く）。
- AI解説の文章は、解析データから機械的に組み立てたサンプルです。質問は、表示される候補にだけ答えます。
- 確認はブラウザの自動操作（幅 360・393・430px）で行いました。実機では確かめていません。
